# Tilda MCP

Tilda MCP — локальный MCP-контур для аккуратной работы агентов с
авторизованным редактором Tilda через ограниченные машинные операции.
Изменения привязаны к точной цели, свежей сессии браузера и локальному
снимку; после одной семантической операции состояние перечитывается и при
необходимости восстанавливается.

**Релиз: 1.0.0, публичный pre-release.** Это не официальный API Tilda, не
универсальный драйвер редактора и не обещание production-надежности. В
публичном репозитории нет реальных ID аккаунта, проектов, страниц и блоков,
клиентского контента, доменов, cookies, профиля браузера и приватных
фикстур.

## Что есть внутри

- MCP stdio-сервер с четырнадцатью семантическими инструментами: статус,
  capabilities, одно разрешение на ограниченную задачу, аудит,
  ограниченное обучение, discovery/query, ChangeSet plan/apply/verify/rollback,
  отдельные publish/unpublish, проверка публичной страницы и фиксированный
  сценарий жизненного цикла страницы.
- Режимы задачи `observe`, `copy-test` и `production` с точными областями
  чтения/записи и коротким сроком действия.
- Адаптеры для подтвержденных строковых полей Standard, кода T123,
  ограниченных операций Zero, SEO и page-specific HEAD, копирования страницы
  в рамках проекта и раскрытия кнопки блока через hover без координатных кликов.
- Снимки и журнал ChangeSet с идемпотентностью, проверкой устаревшего
  состояния, блокировками и защитой путей/симлинков.

## Быстрый запуск

Нужны Node.js 20+ и pnpm 11+.

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test:unit
pnpm build
pnpm smoke:mcp
```

Публичный smoke read-only: он проверяет регистрацию всех 14 инструментов и не
входит в Tilda, не читает удаленные цели, не меняет страницы и не публикует
сайт. Для подключения к Codex используется проектный `.codex/config.toml`.

## Граница безопасности

Перед live-работой оператор сам входит в отдельный браузер, получает свежий
inventory, создает раздельный локальный allowlist лаборатории и авторизует одну
точную задачу. Существующие проекты считаются read-only. Любое изменение идет
по цепочке: `read → snapshot → dry-run → одна операция → reread → diff →
restore/rollback`.

Публикация не является побочным эффектом редактирования и требует отдельного
разрешения. При неизвестной структуре, устаревшей сессии, неоднозначном ответе
или отсутствии доказательства восстановления MCP останавливается. Произвольный
JavaScript, URL, селекторы и координатные макросы не принимаются как команды.

Не заявлены: загрузка assets, массовые каталоги, формы и submissions,
произвольные вложенные Standard/raw HTML, произвольные группы Zero,
межпроектное копирование, folders/trash restore, generic delete, site-wide
HEAD, произвольная проверка доменов и полный Advanced Mode.
